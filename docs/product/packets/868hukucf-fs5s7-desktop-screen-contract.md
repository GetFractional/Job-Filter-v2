### Shared button tiers and link tiers

| Tier | Use | Rule |
| --- | --- | --- |
| primary button | one decisive action for the current surface or module | filled bright-green treatment with the strongest contrast in the current canvas |
| secondary button | meaningful but non-dominant actions such as `Add role` or source alternatives | opaque dark or outlined treatment with clear click affordance |
| utility icon button | toolbar controls such as filter, columns, and sort | compact icon-first control with explicit tooltip or menu label |
| destructive button | remove, archive, or irreversible actions | muted risk treatment only when the action is truly destructive |
| route link | shell nav and local section links | left-aligned text-first treatment with a clear active state |
| inline link | provenance, source, and helper links | text-first treatment with visible hover change and optional underline |

### Hover behavior

- all valid buttons, links, rows, and icon controls must show a visible hover response within the shared shell system
- buttons shift background or border contrast on hover and never remain visually inert
- links shift text contrast and underline or add a restrained surface highlight on hover
- table rows show a clear row-level hover state before selection
- disabled actions do not imitate hover behavior

### Type-aware fields and controls

| Data type | Required desktop control |
| --- | --- |
| short text | inline input or inspector input |
| long text | textarea inside the inspector or editor |
| searchable multi-select | tokenized searchable input with suggestions |
| date | date picker with month and year support |
| numeric | numeric stepper or masked numeric field |
| currency | numeric field plus currency selector |
| boolean | checkbox or switch |
| repeatable record | inline row list with add-row action inside the owning section |
| state field | segmented control or explicit dropdown with explanation |

### Validation, guidance, and error handling

| Concern | Rule |
| --- | --- |
| inline validation | show field-level errors beside the field on blur |
| route-level blocking | only the dominant action disables when critical errors or hard conflicts remain |
| guidance | one-line helpers or tightly scoped tooltips live beside the relevant control only when the field needs extra guidance |
| conflict handling | conflicts show field, current value, new value, source labels, and resolution actions inline or in a drawer |
| trust cues | save state, provenance, and override state stay visible but low-emphasis |

### Add-row and add-record behavior

| Pattern | Rule |
| --- | --- |
| add record | lives inside the owning table toolbar, drawer, or section header |
| add row | creates the row and opens it immediately in the current editor context |
| remove | destructive removes require confirmation only when linked downstream |
| reorder | available where order materially changes meaning, with drag-and-drop plus arrow-button fallback for precision and accessibility |

### Search, sort, and filter rules

| Pattern | Rule |
| --- | --- |
| search | one primary search field leads each queue or table surface |
| sort | explicit menu with persistent state |
| filter | compact menus or drawers with schema-grounded filters only |
| quick filters | acceptable when tied to real work states like `Blockers` or `Hide hard disqualifiers` |
| reject | decorative chips like `Drag to reorder`, `Current role only`, or source labels used as ornamental badges |

### Drawer field and control consistency

- drawer fields use one consistent height family for text inputs, selects, and token inputs inside the same module
- dropdown chevrons stay right-aligned and visually consistent across all select-style controls
- tooltips are reserved for responsibilities, outcomes, hard skills, soft skills, and tools, plus other fields the packet explicitly marks as guidance-heavy
- tooltips render above all layers, remain readable on hover or focus, use title case, and keep normal-weight text
- field values read at normal weight unless semantic emphasis is required

### Table vs board vs drawer vs modal rules

| Surface | Use for | Reject |
| --- | --- | --- |
| table | canonical records, queues, and role matrices | marketing cards or fake dashboards |
| board | active-stage scanning only | D2 history editing or D4 role comparison |
| drawer | quick review, detail inspection, breakdowns, bounded context, or the primary detail editor when the route remains table-led | replacing the main work surface or becoming the only route context |
| modal | one focused edit or confirmation | replacing the main work surface |

- the toolbar must stay on one row at `1440`, `1280`, and `1024`
- search uses an icon-leading compact field with a fixed compact default width that may expand only within remaining toolbar space on focus, never enough to wrap the toolbar
- `Add role` must render as a real button in the shared action system, not as a link or utility icon
- `Filters` and `Columns` may render icon-first if their hover, tooltip, and menu labels stay explicit
- `Company` is the frozen first structural column during horizontal table scroll
- the frozen `Company` lane must keep the role carry-label visible at low emphasis even when the `Role` column is clipped
- company-name cells must stay opaque and structural, not see-through or glassy
- selecting a row opens a real editable detail drawer, not a decorative summary panel
- the drawer is closed by default on first load, opens on row selection, and includes an explicit close control
- auto-save is the default persistence model. An explicit saved-state reassurance may appear, but persistence must not depend on a manual save click
- selected-row styling must read as one continuous highlighted row, not a per-cell broken gradient
- status treatment must stay restrained and professional, with subtle red and green verification cues on the company and role anchor area rather than full-row fills
- group headers must read as structural dividers, not decorative callouts
- interactive rows, group headers, toolbar icons, and jump links must show explicit hover response
- field values render at normal weight unless semantic emphasis is required
- one value per field is the default; secondary values appear only when the schema explicitly owns them
- any approved field that can appear in the drawer may also be surfaced through `Columns`, even when it is not visible by default
- skill-token wrapping and truncation must preserve legibility. Long skill text may wrap to a second line or use restrained end truncation with a tooltip, but it must not clip invisibly

### Structural decisions

- `Add role` belongs in the table toolbar and empty state only
- `Columns` may show, hide, and reorder approved schema columns only
- no arbitrary add-column builder in the first slice
- proof review stays inside the detail drawer or a local nested drawer, not a standalone surface

### Issue model

The first slice handles only these standardized issue types:

1. `Chronology conflict`
2. `Title mismatch`
3. `Scope mismatch`
4. `Current-role ambiguity`
5. `Proof gap`

Every issue must use the field-level question pattern `Which is your truth?` and offer:

- source A
- source B
- enter a different value
- see source
- review later only when the issue is non-blocking

Each issue must show the affected row or field, the competing value or weak claim, the source label, and one jump action back to the exact edit target.

### Explicit rejects

- `Add role` in the page header
- vague columns like `Scope summary` or `Provenance`
- filler labels such as `Selected row`
- low-value chips like `Drag to reorder`, `Current role only`, `Resume + LinkedIn`, or a decorative conflict badge
- full-screen modal editor replacing the table-plus-inspector model
- generic `Proof details` labeling
